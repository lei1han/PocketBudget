# PocketBudget 需求说明

本文档为产品与功能需求的参考口径。具体版本以 `config.json` 与 Git 标签为准。

## WebDAV 同步（第一期）

日期：2026-11-10  
范围：只做 App 内 WebDAV 整包同步，对接用户已有 NAS。不同时做 iCloud，不另做独立同步工具，不迁 SQLite，不扩大到分类/图表/多账户/多币种/云服务自建。

### 目标

在 JSBox 应用内，用 WebDAV 把本地数据整包同步到 NAS 上的一个固定文件，实现多设备（或多份安装）之间的备份与同步。

本地仍是运行时主数据。小组件只读本地，不直接访问 WebDAV。

### 同步对象

一份快照 JSON，必须同时包含：

- 主数据：`version`、`budgets`、`expenses`、`installments`、`installmentItems`（与现有 `data/budget-v1.json` 一致）
- 常用备注：现有 `data/note-presets-v1.json` 的内容（导出/导入与同步口径一致）

快照元数据：

- `schemaVersion`（首期为 1）
- `updatedAt`（ISO 时间）
- `revision`（本地变更递增，用于冲突判定）
- 可选：`deviceId`（本机匿名标识）

导入/同步拉取时必须校验结构；校验失败不得覆盖本地。

### 同步模型

1. 开关关闭或未配置完整时：完全离线，行为与现版一致。
2. 打开或回到前台：若已启用且配置完整，先拉取远程快照再决定。
3. 本地保存成功后：若已启用，再推送。
4. 设置页提供「立即同步」。
5. 冲突：本地 dirty 且远程 `revision` 与上次成功同步记录不同 → 用户二选一「保留本地并上传」或「使用云端」；禁止逐条自动合并。
6. 远程文件不存在：MKCOL 建目录（容忍已存在），首次推送本地上传。
7. 不得把远程读失败或空响应当作「云端为空」。

### 配置与安全

- 启用、服务器 HTTPS 地址、用户名、`$keychain` 密码、远程路径（默认 `/PocketBudget/pocketbudget.json`）
- 测试连接、立即同步、最近同步状态
- 拒绝 `http://`（启用时）
- HTTPS + Basic 认证

### 界面

遵循 `docs/design/PocketBudget-设计规范.md`。设置保留「数据」「应用」分组；WebDAV 为「数据」下子页入口。

### 验收（第一期）

1. 未配置或关闭同步时，现有功能不变。
2. 测试连接可区分成功、认证失败、不可达。
3. 双设备同步含常用备注。
4. 双端修改后冲突二选一。
5. 远程缺失不清本地，首次上传。
6. 导出/导入 JSON 含常用备注。
7. 版本 1.4.0，可打包 `PocketBudget.box`。

### 不做（第一期）

iCloud、自建同步服务、逐条合并、多远端、后台定时同步、预算数据上 GitHub。
